# Skills 与 MCP

## Skills

Skill 是让 Agent 在相关任务中按需读取的说明包，不会单凭文本获得工具权限。Ja 会先展示名称和描述；模型需要使用时，再通过 `read(skill://名称/SKILL.md)` 读取正文。若包内有参考文件，也通过 `skill://名称/相对路径` 按需读取。

一个本地 Skill 是名为小写字母、数字及连字符的目录，里面至少有 `SKILL.md`：

```markdown
---
name: my-skill
description: 处理某类具体任务时使用的说明。
---

# 操作说明
```

目录名须与 `name` 相同。默认来源依优先级从低到高为内置、`~/.agents/skills`、`~/.ja/skills`、可信项目从 Git 根到当前目录的 `.agents/skills`；Windows 的 `~` 对应 `%USERPROFILE%`。同名时高优先级包整体覆盖低优先级包，参考文件不会跨包混用。未信任项目的 Skill 不参与发现。全局 `disabled_skills` 可停用 `user:` 或 `ja:` 来源；项目列表可再包含 `project:`，且项目显式列表整体替换全局列表。内置来源不能通过该字段停用，但可被同名用户包覆盖。

桌面 **设置 -> Skills** 展示内置、用户、Ja 和项目来源以及可用状态。改变包的名称或描述后，需等下一次发现；正文和参考文件在下一次读取时使用当前内容。正在执行的请求仍以自己的运行状态为准。

## MCP

MCP 为 Agent 增加外部工具。桌面 **设置 -> MCP** 可新增、编辑、启停和测试服务，并查看发现的工具；`stdio` 启动本机程序，`streamable_http` 连接远端服务。Ja 当前只提供 Tools 的列举和调用；不要假定 OAuth、MCP Resources、Prompts 或其它协议能力可用。

配置服务时先确认可执行文件或 URL、参数、环境变量和鉴权方式。密钥使用 Ja 的凭据入口保存，配置里仅保留 `credential_id` 引用。服务“已保存”不代表已连通；使用设置页的测试和工具目录查看结果。会话概览展示该会话最近观察到的 MCP 状态；未检查或旧状态不能当作实时可用。可信项目可按稳定 `mcp_id` 覆盖全局服务，撤销信任后项目服务不再用于新的调用。

MCP 工具仍遵守 Ja 的执行确认、Workspace 信任和运行时边界。停用或删除服务前，检查是否有正在使用它的任务；连接中断或工具结果未知时，先核实外部副作用，不要直接重试写操作。
