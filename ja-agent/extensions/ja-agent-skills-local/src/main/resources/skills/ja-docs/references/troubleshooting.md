# 故障与恢复

## 找不到模型或无法发送

打开 **设置 -> 模型**，检查是否至少有一个可用 Provider、真实上游模型标识和已配置凭据。新建 Provider 后先保存，再选择模型；需要测试连接时使用“验证模型”，它会发出真实请求。连接错误要区分 API 规范、Base URL、模型标识与凭据状态；不要把 Provider 显示名称当作模型标识。配置或凭据缺失一般不应阻断查看历史，修复后可继续使用原会话。

仅使用 CLI 时运行 `ja setup`，或从 `/model` 进入“管理模型”。配置已保存而密钥失败时，只补齐未完成步骤；回执未知时按 `F5` 核实，不重复创建供应商或重发写入。所选会话模型已删除时通过 `/model` 重新选择，后台不会静默替换既有会话模型。

## 配置出现问题

Ja Home 默认在 Windows 的 `%USERPROFILE%\.ja`；`config.toml` 是用户配置，可信项目的 `<workspace>\.ja\config.toml` 是稀疏覆盖。先看设置页报告的字段问题和生效值，确认是全局还是项目层。普通保存使用版本检查，遇到冲突应重新读取并保留原草稿。语法损坏时不要用普通 patch 覆盖；只在明确了解可能舍弃内容后使用 Ja 的备份修复流程。`auth.json` 是受保护的凭据存储，不要手工修补、打印或复制进对话。

## 会话等待、中断或结果未知

“等待批准”“等待输入”需要处理对应卡片；收到受理回执仍需等服务端终态。取消已受理也可能仍在清理，应回读同一会话，直至显示 `completed`、`failed` 或 `cancelled`。应用或后台重启后，未完成任务可能变成暂停状态；使用原会话的“继续回复”或恢复入口，不要另开新任务来假装原操作成功。

Shell、MCP 或外部写入在中断时可能已经产生副作用。遇到“结果未知”先检查实际目标，再在原恢复卡中选择重新执行或跳过；跳过不表示成功。计划停止、会话归档或客户端断开都不自动撤销已经写入的文件。

## 数据与反馈

对话、配置和附件默认保存在本机 `~/.ja`（Windows 为 `%USERPROFILE%\.ja`）。不要通过删除整个 Ja Home 来排障。反馈问题时提供 Ja 版本、操作系统、复现步骤、可见错误和任务终态；截图、日志及示例配置先移除 API Key、私有文件内容和个人路径。安装包的更新与公开发布状态以实际安装版本为准。
