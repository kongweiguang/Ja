# JA RPC 2.0 method closure

| Method                   | Parameters                                                                                     | Ownership rule                                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `runtime/initialize`     | protocol/version, capabilities, limits                                                         | capabilities contain no Host Tool bridge                                                                                                               |
| `runtime/context/register` | exact `{environment,shell,clientProcessId,clientLifetimeId}` | authenticated Native registers its private execution context and process-lifetime owner; PID is a positive safe integer and lifetime ID is `native_` plus 32 lowercase hex characters |
| `runtime/client/close` | exact `{timeoutMs}` with integer `1..20000` | closes only the current registered Native owner's temporary roots; exact `{accepted:true}` acknowledges completed cleanup, not global server shutdown |
| `runtime/shutdown` | `{force?:boolean}` | default refuses pending work; explicit force enters bounded cancellation, success returns accepted and shutting_down |
| `runtime/health` | exact `{}` | authenticated connection reports current runtime readiness |
| `runtime/storage/retry` | exact `{recoveryId}` | retries only the currently reported blocked recovery; the server owns all database paths and the caller cannot select or restore a database |
| `operation/read` | exact `{operationKey,sourceThreadId?}` | without sourceThreadId reads Core/Turn receipts; with sourceThreadId reads only that source owner's thread/fork receipt; committed returns method, owner threadId and the original result; unknown never authorizes blind replay; Plan, Interaction, and Task keep their own receipts |
| `workspace/path/search`  | exact `{threadId,workspaceId,query,limit?}`                                                    | searches names/relative paths only under fixed server budgets; it never reads file bodies or starts hidden Files/Review work                           |
| `workspace/open` | exactly one of `{cwd}` or `{workspaceId}` | Java creates random stable PROJECT identities; an existing ID reopens its registered project/session directory and never derives project identity from a path |
| `workspace/read` | exact `{workspaceId}` | reads registered metadata from SQLite without touching the directory, configuration or native resources; missing directories remain readable |
| `workspace/update` | `{workspaceId,expectedRevision,displayName?,cwd?}` with at least one changed field | PROJECT-only atomic CAS; display name does not rename disk folders and may update while busy or unavailable; changed root requires an available unowned real directory, the shared Turn/Plan admission barrier and trust reset |
| `thread/create`          | optional `cwd`, title, `providerId`, `modelId`, nullable `reasoningLevel`, `accessMode`        | freezes the relative-path base and explicit Thread preferences                                                                                         |
| `thread/fork`            | exact `{sourceThreadId,sourceItemId,expectedThreadRevision,operationKey}`                       | includes the selected durable final_answer and its earlier history under revision CAS; creates a distinct idle Thread with its own frozen history and context; execution and approvals stay in the source Thread |
| `thread/read` | `{threadId,cursor?,limit?,tail?:true}` | returns inherited prefix and native items in one ordered cursor stream; each item and display Turn requires origin native or inherited; tail starts at the newest page and pages backward; public text previews are limited to 512 Unicode code points with required totalCharacters and truncated |
| `thread/item-content/read` | exact `{threadId,itemId,offsetCharacters,limitCharacters}` | reads 1–65,536 Unicode code points from native or inherited current-path public text; inherited content belongs to the target Thread and remains readable after source deletion; stale-path items, Tools, and private reasoning are not readable |
| `history/input/search` | `{query,cursor?,limit?}` with at most 10 results | searches persisted main-conversation USER_INPUT text in recent-first keyset order; each result carries a bounded preview and `truncated` so clients cannot mistake an incomplete draft for the original input |
| `thread/observe` / `thread/unobserve` | exact `{threadId}` | add or remove only this connection's Thread detail events; both return `{accepted:true,threadId}` |
| `thread/list` | `{workspaceId,cursor?,limit?}` or `{scope:"all",query?,workspaceId?,cursor?,limit?}` | Workspace navigation lists main conversations; explicit all-scope discovers lightweight main/side-chat/subagent metadata, excluding closing subtrees |
| `thread/usage/read` | exact `{threadId}` | returns only persisted diagnostic coverage and token totals; it neither loads transcript pages nor accepts filters, prices, or Provider overrides |
| `thread/mcp/read` | exact `{threadId}` | reads the Thread's redacted MCP projection without connecting to or probing any service |
| `thread/pin`             | exact `{threadId,pinned,expectedThreadRevision}`                                               | updates `pinned_at` by revision CAS and returns the complete authoritative Thread                                                                      |
| `thread/seen`            | exact `{threadId,expectedThreadRevision}`                                                      | advances the durable latest-Turn seen boundary by revision CAS and returns the complete authoritative Thread                                           |
| `thread/archive`         | exact `{threadId,expectedThreadRevision}`                                                      | rejects non-terminal Turns, clears Pin, hides the Thread from active lists, and returns the archived Thread                                            |
| `thread/restore`         | exact `{threadId,expectedThreadRevision}`                                                      | restores only an archived Thread, keeps it unpinned, and returns the active Thread                                                                     |
| `thread/compact`         | exact `{threadId, expectedThreadRevision}`                                                     | only an idle Thread may be compacted; Java resolves its bound Provider/Model and owns all Token counting, Summary, MCP lease, Checkpoint, and CAS work |
| `thread/compact/cancel`  | exact `{threadId}`                                                                             | requests cancellation of the current connection's active manual compaction; returns `{accepted:boolean}` without claiming the original request has terminated |
| `plan/read`              | exact `{threadId,planId}`                                                                      | returns one Thread-owned Plan with nullable draft/current revision/approval and its standalone step executions                                         |
| `plan/revisions/list`    | `threadId`, `planId`, optional cursor and limit                                                | pages immutable structured revisions without parsing Markdown                                                                                         |
| `plan/create`            | Thread owner, objective, Thread revision CAS and `operationKey`                               | atomically creates an independent Thread-owned editable Plan                                                                                           |
| `plan/draft/save`        | Plan CAS, `operationKey` and structured Plan definition                                      | validates stable IDs and a bounded acyclic step graph                                                                                                  |
| `plan/draft/discard`     | Plan CAS and `operationKey`                                                                   | discards only the editable draft; an earlier approved revision is not silently changed                                                                 |
| `plan/propose`           | Plan CAS and `operationKey`                                                                   | freezes the current draft as an immutable canonical JSON revision                                                                                      |
| `plan/execute`           | Plan CAS, `operationKey`, `planRevisionId` and `planHash`                                     | atomically confirms the exact proposed revision, records approval audit, and creates one standalone Plan-owned Run and hidden `PLAN_EXECUTION` Turn        |
| `plan/reject`            | Plan CAS, `operationKey` and reason                                                           | rejects the pending revision and returns the Plan to editable planning                                                                                 |
| `task/create`            | parent Thread/Turn, expected parent revision, task name, optional preferences                 | user-only `SIDE_TASK`; atomically creates an idle Child Thread with a frozen effective-context seed and projection                                  |
| `task/list`              | exact `{rootThreadId}`                                                                         | returns at most 64 descendants from the Java-owned projection without materializing Child transcripts                                                  |
| `task/read`              | task Thread plus optional `task:<activitySequence>:<mailboxSequence>` cursor and limit          | returns lineage, bounded seed preview, low-frequency activity and mailbox; detailed transcript remains `thread/read`                                   |
| `task/observe`           | task Thread and expected task revision                                                         | opens an independent connection-scoped observation on every call and returns an opaque handle                                                          |
| `task/unobserve`         | exact observation handle                                                                       | releases only the current connection's handle; an unknown or already released handle returns `TASK_OBSERVATION_INVALID`                                  |
| `task/seen`              | task Thread, projection revision, through activity sequence                                    | advances the durable unread boundary by CAS                                                                                                            |
| `thread/message/send`    | sender/target Thread, structured content, `operationKey`                                      | ordered mailbox write across live Threads; never starts, interrupts, or auto-replies in the target Thread                                            |
| `task/followup`          | message fields, expected task revision and `operationKey`                                     | persists a `FOLLOW_UP` and starts or queues a new Child Turn                                                                                           |
| `task/cancel`            | task Thread and expected task revision                                                         | recursively cancels only `ATTACHED` descendants; independent side tasks survive ancestor cancellation                                                  |
| `task/tree/delete`       | task Thread, expected revision, exact repeated confirmation identity                           | the only operation allowed to delete a complete task subtree                                                                                           |
| `task/close`             | task Thread identity                                                                         | closes a temporary side task after cancelling its work and releasing its observations; the operation is idempotent and does not delete delivered messages |
| `attachment/import`      | exact `{ingressToken,workspaceId,displayName,sizeBytes,sha256}`                                | Rust private staging is revalidated and copied into Java-owned managed storage; paths are forbidden                                                    |
| `attachment/discard`     | exact `{attachmentId}`                                                                         | only an unbound draft can move to the discarded terminal state                                                                                         |
| `attachment/preview/open` | exact `{attachmentId,authorization}` where authorization is `draft+workspaceId` or `thread+threadId` | Java reauthorizes each open against an unreserved draft or the Thread's queued/message relation; old `bound` authorization is invalid                |
| `attachment/preview/read` | exact `{previewSessionId,offsetBytes,limitBytes}`                                               | reads only the already-authorized bounded preview session                                                                                              |
| `attachment/preview/close` | exact `{previewSessionId}`                                                                     | idempotently releases one opaque preview session                                                                                                       |
| `turn/start`             | `{threadId,content,operationKey,runtimeOverrides?}` with non-empty `content[]`; overrides allow only `modelId`, `accessMode`, and `outputSchema` | Java freezes the authoritative Thread revision; admission CAS conflicts receive one server reread before `CONFLICT`; attachments bind atomically |
| `turn/continue`          | exact `{threadId,expectedThreadRevision,operationKey}`                                       | continues the latest stopped unanswered question through a hidden Turn without adding a USER message                                                  |
| `turn/reask`             | exact `{threadId,expectedThreadRevision,sourceMessageId,content,operationKey}`               | edits only that latest question; Java atomically selects the new current path and retains old attempts for audit                                      |
| `turn/resume`            | exact `{turnId, expectedThreadRevision}`                                                       | explicitly authorizes only the earliest resumable suspended Turn; the next Provider request resolves the latest environment                           |
| `turn/recovery/respond`  | exact `{turnId,callId,expectedThreadRevision,expectedRecoveryRevision,decision,operationKey}` | records one explicit `retry` or `skip` for the earliest unknown Tool; a settled final item reuses `turn/resume`, while another unknown item remains in place |
| `turn/cancel`            | exact `{turnId}`                                                                                | idempotently claims the globally unique Turn stop intent; Java reads current Thread/Turn versions in SQLite, cancels queued/running/waiting/suspended Turns, and returns the first claim or current terminal ACK |
| `turn/input/enqueue`     | exact `{turnId,content,kind,operationKey}`; `kind` is `steering` or `follow_up`            | atomically appends one durable input and operation receipt; each Turn accepts at most eight inputs and 512 KiB of queued JSON content                 |
| `turn/input/prioritize`  | exact `{turnId,inputId,expectedInputRevision}`                                                 | changes the pending input to `steering` and places it after earlier prioritization clicks but before every `follow_up`                                 |
| `turn/input/update`      | exact `{turnId,inputId,expectedInputRevision,content}`                                         | replaces only an unconsumed structured input and advances both its revision and the authoritative queue revision                                       |

| `process/read`            | exact `{workspaceId,threadId,generation,sessionId,afterSequence,maxBytes}`                     | reads bounded incremental output for that Thread-owned session and generation                                                                         |

| `review/start`           | exact `{threadId,expectedThreadRevision,operationKey,snapshotAttachmentId}`                  | starts one read-only review Turn against the imported frozen snapshot                                                                                   |
| `review/read`            | exact `{threadId,turnId}`                                                                    | returns the review Turn state and, after completion, its persisted report bound to the frozen snapshot                                                |
| `approval/respond`       | approval id, turn id, decision, revision and `operationKey`                                   | resolves one Tool request only                                                                                                                         |
| `configuration/read`     | optional trusted `workspaceId`                                                                  | returns redacted effective/user/project layers, field sources, issues, and independent CAS versions; it never exposes paths or credentials             |
| `configuration/replace`  | user full v2 document, or trusted sparse project v2 document                                    | Atomically replaces exactly the target scope by CAS; project routes require a complete API/base URL/credential reference tuple; project Models merge by stable ID; Secret remains in the user vault |
| `configuration/patch`    | user or trusted project merge patch with the scope CAS                                         | project Provider patches are keyed by provider ID and nested Model patches by model ID, preserving unrelated raw entries; it never accepts a file path   |
| `configuration/reset`    | target scope and CAS                                                                           | removes the target configuration layer; the next project Skill operation recreates only its minimal project document                                  |
| `skill/list`             | optional `workspaceId`, cursor and limit                                                       | discovers the effective user, Ja, and trusted project Skill catalog metadata without exposing paths or document bodies                                 |

Configuration, credential, workspace, history, catalog, health, and shutdown methods remain those listed by the schema. Unknown methods and fields fail closed.

`credential/reveal-provider` accepts exactly `{providerId}` and is the sole read exception for an API Key: it returns the nullable Key bound to that Provider only while its edit form is open. It does not accept a `credentialId`, does not expose MCP credentials, and is not part of `configuration/read` or configuration events.

The handshake capability object includes exact `collaborationModes=["default","plan"]` and the feature closure defined by the schema. Collaboration mode is orthogonal to AccessMode. Child Threads stay out of Workspace navigation; explicit `thread/list` with `scope:"all"` discovers them across the local instance without reading transcripts.

`task/read` omits `cursor` for the first page; an explicit `null`, an opaque value, a signed sequence, or a value above the JavaScript safe-integer boundary is invalid. `task/list` returns one complete rooted tree: identities are unique, every non-root parent must be present, and each child depth is exactly its parent's depth plus one. Every `subagent + attached` summary has a non-null `originTurnId` anchoring cancellation and causality; a side task may have a nullable parent Turn.

`thread/compact` never sends a normal assistant generation. A stale revision returns `CONFLICT`, a non-terminal Turn returns `THREAD_BUSY`, and a missing Thread returns `THREAD_NOT_FOUND`. Official Provider Token counting or Summary failure is reported through the stable context error subset; no Provider response body crosses JA-RPC.
When no facts can be evicted and the compacted envelope would not be smaller, `thread/compact` returns `unchanged` without calling the Summary model or advancing Thread revision; this is a normal result, not `CONTEXT_LIMIT`.
The desktop caller waits for the authoritative response or session closure without a fixed compaction request deadline. Closing the session cancels the operation; an uncertain response must be reconciled before another mutation attempt.
The same connection may send `thread/compact/cancel` while the request is pending. An `accepted:true` ACK records only cancellation intent; the original response and authoritative Thread history decide whether a Checkpoint committed before cancellation. `accepted:false` means this connection has no active compaction for that Thread.

`turn/start` does not accept the removed top-level `input` or `text` fields. Content is exactly text, attachment, `workspace_reference {workspaceId,relativePath,kind}`, or `skill_reference {skillId}`. Context references precede attachments and at most one final text block. A Skill alone is not sendable; Workspace references do not preload or expand content. Optional `runtimeOverrides` applies only to that admitted Turn: `modelId` and `accessMode` select its runtime, while `outputSchema` requests a structured final answer. The selected model must declare `capabilities.supports_output_schema=true`; when omitted from a model's configuration, that capability is false. Runtime overrides are frozen with the Turn and cannot be supplied to `turn/resume`.

`turn/resume` does not accept content, deadline, current runtime overrides, compatibility aliases, or an additional operation identity. Its `turnId` is the Operation identity. A suspended Turn remains visible in `thread/read` until explicit resume or cancel; resume returns the existing Turn identity and a newly committed Thread revision.

`turn/recovery/respond` does not accept recovery evidence, file content, execution cursor, or a synthetic success result. `retry` is the user's explicit acceptance of repeat risk; `skip` persists a Tool error result for the model without claiming the target completed. Both choices are guarded by the current Thread and recovery revisions plus an idempotency key.

Queued content uses the same tagged union and is capped at 524,288 compact JSON bytes. Queue mutations never
advance the execution CAS or interrupt an in-flight Provider or Tool call. The returned `inputQueue.items`
array is the authoritative consumption order; mutation callers use `inputRevision` as item-level CAS.

Attachment preview authorization is a strict tagged union. `draft` carries only `workspaceId` and is valid only
for an unreserved draft in that Workspace; `thread` carries only `threadId` and covers both queue reservations and
message-bound attachments owned by that Thread. Every read revalidates the opaque preview session; HTML and URL
content never broadens this authorization.

Frozen Turn changes are Java-owned immutable artifacts. `turn/change-set/read` binds the exact Thread, Turn, artifact, and relative file path on every request; it returns no current workspace content and never accepts pagination state. Absolute, parent-escaping, control-character, backslash and drive-prefixed paths never cross the contract.

Review reports bind each finding to the exact `{path,layer}` in `coverage.filesReviewed`; `layer` is one of `staged`, `unstaged`, `untracked`, or `comparison`. This keeps findings unambiguous when a path exists in multiple Git layers. The finding `side` separately selects `base` or `current` content within that frozen file identity.

There is no running-Turn change preview method, preview session, revision notification, or feature flag. Consumers use Git for current workspace state and request frozen content only after the selected Turn has settled.

## 交互提问与计划执行

`interaction/read {threadId,interactionId?}` 返回交互、可恢复草稿、事件水位和 `resumeState`；无指定身份时读取当前问题或已回答但仍待恢复的交互。`interaction/observe {threadId}` 先注册再返回相同快照及连接私有 `observationId`，`interaction/unobserve` 只释放观察。

`interaction/draft/save` 接受 `threadId`、`interactionId`、`expectedDraftRevision`、`operationKey`、结构化 `answers`、`page` 与 `collapsed`。`interaction/respond` 用 `expectedInteractionRevision` 和 `operationKey` 原子提交答案、原 ToolResult 与恢复游标，并安排原 Turn 恢复；调用方观察终态，不在回答后立即另发 `turn/resume`。响应未知时用同键、同版本和同答案重试，已结算请求返回原结果；同键改答案返回 `INTERACTION_INVALID_STATE`，新键提交旧版本返回 `INTERACTION_REVISION_CONFLICT`。`interaction/cancel` 明确取消，收起卡片不调用它。答案区分稳定选项、自填和跳过，最多三题；服务端重新校验必答及选项归属。等待不自动超时同意，也不授予执行权限。

`plan/current/read {threadId}` 返回 nullable `current`；`plan/observe {threadId,planId}` 返回快照及观察句柄。Plan 独立事件和证据分别通过 `plan/events/read`、`plan/evidence/list` 分页，后者必须绑定 `planRevisionId` 与 `runId`。

`plan/execute` 绑定用户看到的版本与 hash，在单个事务中授权并创建 Run。`plan/pause`、`plan/resume`、`plan/stop` 接受 `{threadId,planId,expectedPlanRevision,runId,operationKey}`。草稿定稿仍使用 `plan/propose`，界面显示“完成编辑”；用户开始执行只点击“执行”。
