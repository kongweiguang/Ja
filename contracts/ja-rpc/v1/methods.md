# JA RPC v1 method closure

| Method                   | Parameters                                                                                     | Ownership rule                                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `runtime/initialize`     | protocol/version, capabilities, limits                                                         | capabilities contain no Host Tool bridge                                                                                                               |
| `workspace/path/search`  | exact `{threadId,workspaceId,query,limit?}`                                                    | searches names/relative paths only under fixed server budgets; it never reads file bodies or starts hidden Files/Review work                           |
| `thread/create`          | optional `cwd`, title, `providerId`, `modelId`, nullable `reasoningLevel`, `accessMode`        | freezes the relative-path base and explicit Thread preferences                                                                                         |
| `thread/list` | `{workspaceId,cursor?,limit?}` or `{scope:"all",query?,workspaceId?,cursor?,limit?}` | Workspace navigation lists main conversations; explicit all-scope discovers lightweight main/side-chat/subagent metadata, excluding closing subtrees |
| `thread/pin`             | exact `{threadId,pinned,expectedThreadRevision}`                                               | updates `pinned_at` by revision CAS and returns the complete authoritative Thread                                                                      |
| `thread/seen`            | exact `{threadId,expectedThreadRevision}`                                                      | advances the durable latest-Turn seen boundary by revision CAS and returns the complete authoritative Thread                                           |
| `thread/archive`         | exact `{threadId,expectedThreadRevision}`                                                      | rejects non-terminal Turns, clears Pin, hides the Thread from active lists, and returns the archived Thread                                            |
| `thread/restore`         | exact `{threadId,expectedThreadRevision}`                                                      | restores only an archived Thread, keeps it unpinned, and returns the active Thread                                                                     |
| `thread/compact`         | exact `{threadId, expectedThreadRevision}`                                                     | only an idle Thread may be compacted; Java resolves its bound Provider/Model and owns all Token counting, Summary, MCP lease, Checkpoint, and CAS work |
| `goal/read`              | exact `{goalId}`                                                                               | returns the complete Java-owned Goal projection, including a nullable `GoalPlanLink`                                                                    |
| `goal/events/read`       | `goalId`, optional cursor and limit                                                            | pages the durable Goal event stream; it is not an execution transcript                                                                                 |
| `goal/observe`           | exact `{goalId}`                                                                               | creates a connection-scoped high-frequency observation handle                                                                                         |
| `goal/unobserve`         | exact `{observationId}`                                                                        | idempotently releases only the current connection's Goal handle                                                                                        |
| `plan/read`              | exact `{threadId,planId}`                                                                      | returns one Thread-owned Plan with nullable draft/current revision/approval and its standalone step executions                                         |
| `plan/revisions/list`    | `threadId`, `planId`, optional cursor and limit                                                | pages immutable structured revisions without parsing Markdown                                                                                         |
| `goal/evidence/list`     | `goalId`, `goalDefinitionRevision`, optional `planRevisionId`, cursor and limit                | returns current-definition evidence for either a planless Goal Run or the explicitly linked Plan revision                                             |
| `goal/create`            | owner, objective, acceptance criteria, revision zero and idempotency key                       | atomically creates one active Java-owned Goal and a planless Goal Run                                                                                  |
| `goal/plan/attach`       | Goal CAS, idempotency key, `planId`, `planRevisionId` and `planHash`                            | explicitly links an approved exact Plan revision and creates a distinct Goal-owned Run only after all recovery blockers settle                         |
| `goal/plan/detach`       | Goal CAS and idempotency key                                                                   | explicitly removes the nullable link at a safe settlement point and creates a new planless Goal Run while preserving history                           |
| `goal/pause`             | Goal CAS and idempotency key                                                                   | persists paused state before cancellation is propagated                                                                                                |
| `goal/resume`            | Goal CAS and idempotency key                                                                   | resumes only when approval, input and recovery gates permit                                                                                            |
| `goal/stop`              | Goal CAS and idempotency key                                                                   | persists the explicit stopped terminal state                                                                                                           |
| `plan/create`            | Thread owner, objective, Thread revision CAS and idempotency key                               | atomically creates an independent Thread-owned editable Plan                                                                                           |
| `plan/draft/save`        | Plan CAS, idempotency key and structured Plan definition                                      | validates stable IDs and a bounded acyclic step graph                                                                                                  |
| `plan/draft/discard`     | Plan CAS and idempotency key                                                                   | discards only the editable draft; an earlier approved revision is not silently changed                                                                 |
| `plan/propose`           | Plan CAS and idempotency key                                                                   | freezes the current draft as an immutable canonical JSON revision                                                                                      |
| `plan/execute`           | Plan CAS, idempotency key, `planRevisionId` and `planHash`                                     | atomically confirms the exact proposed revision, records approval audit, and creates one standalone Plan-owned Run and hidden `PLAN_EXECUTION` Turn        |
| `plan/reject`            | Plan CAS, idempotency key and reason                                                           | rejects the pending revision and returns the Plan to editable planning                                                                                 |
| `task/create`            | parent Thread/Turn, expected parent revision, task name, optional preferences                 | user-only `SIDE_TASK`; atomically creates an idle Child Thread with a frozen effective-context seed and projection                                  |
| `task/list`              | exact `{rootThreadId}`                                                                         | returns at most 64 descendants from the Java-owned projection without materializing Child transcripts                                                  |
| `task/read`              | task Thread plus optional `task:<activitySequence>:<mailboxSequence>` cursor and limit          | returns lineage, bounded seed preview, low-frequency activity and mailbox; detailed transcript remains `thread/read`                                   |
| `task/observe`           | task Thread and expected task revision                                                         | opens one connection-scoped high-frequency observation and returns an opaque handle                                                                    |
| `task/unobserve`         | exact observation handle                                                                       | idempotently releases only the current connection's handle                                                                                             |
| `task/seen`              | task Thread, projection revision, through activity sequence                                    | advances the durable unread boundary by CAS                                                                                                            |
| `thread/message/send`    | sender/target Thread, structured content, idempotency key                                      | ordered mailbox write across live Threads; never starts, interrupts, or auto-replies in the target Thread                                            |
| `task/followup`          | message fields plus expected task revision                                                     | persists a `FOLLOW_UP` and starts or queues a new Child Turn                                                                                           |
| `task/cancel`            | task Thread and expected task revision                                                         | recursively cancels only `ATTACHED` descendants; independent side tasks survive ancestor cancellation                                                  |
| `task/tree/delete`       | task Thread, expected revision, exact repeated confirmation identity                           | the only operation allowed to delete a complete task subtree                                                                                           |
| `task/close`             | task Thread identity                                                                         | closes a temporary side task after cancelling its work and releasing its observations; the operation is idempotent and does not delete delivered messages |
| `attachment/import`      | exact `{ingressToken,workspaceId,displayName,sizeBytes,sha256}`                                | Rust private staging is revalidated and copied into Java-owned managed storage; paths are forbidden                                                    |
| `attachment/discard`     | exact `{attachmentId}`                                                                         | only an unbound draft can move to the discarded terminal state                                                                                         |
| `attachment/preview/open` | exact `{attachmentId,authorization}` where authorization is `draft+workspaceId` or `thread+threadId` | Java reauthorizes each open against an unreserved draft or the Thread's queued/message relation; old `bound` authorization is invalid                |
| `attachment/preview/read` | exact `{previewSessionId,offsetBytes,limitBytes}`                                               | reads only the already-authorized bounded preview session                                                                                              |
| `attachment/preview/close` | exact `{previewSessionId}`                                                                     | idempotently releases one opaque preview session                                                                                                       |
| `turn/start`             | `threadId`, non-empty `content[]`, optional deadline                                           | `content` is the strict four-part union; Java validates Workspace/Skill references and atomically binds attachments                                    |
| `turn/resume`            | exact `{turnId, expectedThreadRevision}`                                                       | explicitly authorizes only the earliest resumable suspended Turn; the next Provider request resolves the latest environment                           |
| `turn/cancel`            | turn id and expected Thread revision                                                           | cancels the Turn and all pending inputs                                                                                                                |
| `turn/input/enqueue`     | exact `{turnId,content}`                                                                       | appends one durable `follow_up`; each Turn accepts at most eight inputs and 512 KiB of queued JSON content                                             |
| `turn/input/prioritize`  | exact `{turnId,inputId,expectedInputRevision}`                                                 | changes the pending input to `steering` and places it after earlier prioritization clicks but before every `follow_up`                                 |
| `turn/input/update`      | exact `{turnId,inputId,expectedInputRevision,content}`                                         | replaces only an unconsumed structured input and advances both its revision and the authoritative queue revision                                       |
| `turn/input/delete`      | exact `{turnId,inputId,expectedInputRevision}`                                                 | resolves only an unconsumed input; a stale item revision fails with `CONFLICT`                                                                         |
| `tool/artifact/read`     | `threadId`, `turnId`, `callId`, `artifactId`, character offset/limit                           | reads only the redacted Tool artifact owned by that exact identity tuple; the page limit is 65,536 characters                                          |
| `turn/change-set/read`   | exact `{threadId,turnId,artifactId,filePath}`                                                | returns one complete persisted UTF-8 Diff file as standard Base64, capped at 2 MiB and bound to its lowercase SHA-256                                  |
| `approval/respond`       | approval id, turn id, `approve` or `deny`, revision                                            | resolves one Tool request only                                                                                                                         |
| `skill/list`             | optional `workspaceId`, cursor and limit                                                       | discovers the effective built-in, user, Ja, and trusted project Skill catalog without exposing paths or document bodies                                |
| `model/test`             | exact saved `providerId` and `modelId`                                                         | sends one bounded request without history, Tools, or attachments; returns only redacted response model and latency                                     |

Configuration, credential, workspace, history, catalog, health, and shutdown methods remain those listed by the schema. Unknown methods and fields fail closed.

The handshake capability object includes exact `collaborationModes=["default","plan"]` and the feature closure defined by the schema. Collaboration mode is orthogonal to AccessMode. Child Threads stay out of Workspace navigation; explicit `thread/list` with `scope:"all"` discovers them across the local instance without reading transcripts.

`task/read` omits `cursor` for the first page; an explicit `null`, an opaque value, a signed sequence, or a value above the JavaScript safe-integer boundary is invalid. `task/list` returns one complete rooted tree: identities are unique, every non-root parent must be present, and each child depth is exactly its parent's depth plus one. Every `subagent + attached` summary has a non-null `originTurnId` anchoring cancellation and causality; a side task may have a nullable parent Turn.

`thread/compact` never sends a normal assistant generation. A stale revision returns `CONFLICT`, a non-terminal Turn returns `THREAD_BUSY`, and a missing Thread returns `THREAD_NOT_FOUND`. Official Provider Token counting or Summary failure is reported through the stable context error subset; no Provider response body crosses JA-RPC.

`turn/start` does not accept the removed top-level `input` or `text` fields. Content is exactly text, attachment, `workspace_reference {workspaceId,relativePath,kind}`, or `skill_reference {skillId}`. Context references precede attachments and at most one final text block. A Skill alone is not sendable; Workspace references do not preload or expand content.

`turn/resume` does not accept content, deadline, current runtime overrides, compatibility aliases, or an additional operation identity. Its `turnId` is the Operation identity. A suspended Turn remains visible in `thread/read` until explicit resume or cancel; resume returns the existing Turn identity and a newly committed Thread revision.

Queued content uses the same tagged union and is capped at 524,288 compact JSON bytes. Queue mutations never
advance the execution CAS or interrupt an in-flight Provider or Tool call. The returned `inputQueue.items`
array is the authoritative consumption order; mutation callers use `inputRevision` as item-level CAS.

Attachment preview authorization is a strict tagged union. `draft` carries only `workspaceId` and is valid only
for an unreserved draft in that Workspace; `thread` carries only `threadId` and covers both queue reservations and
message-bound attachments owned by that Thread. Every read revalidates the opaque preview session; HTML and URL
content never broadens this authorization.

Frozen Turn changes are Java-owned immutable artifacts. `turn/change-set/read` binds the exact Thread, Turn, artifact, and relative file path on every request; it returns no current workspace content and never accepts pagination state. Absolute, parent-escaping, control-character, backslash and drive-prefixed paths never cross the contract.

There is no running-Turn change preview method, preview session, revision notification, or feature flag. Consumers use Git for current workspace state and request frozen content only after the selected Turn has settled.

## 交互提问与计划执行

`interaction/read {threadId,requestId?}` 返回请求、可恢复草稿、事件水位和 `resumeState`；无指定身份时读取当前问题或已回答但仍待恢复的请求。`interaction/observe {threadId}` 先注册再返回相同快照及连接私有 `observationId`，`interaction/unobserve` 只释放观察。

`interaction/draft/save` 接受 Thread/request identity、`expectedDraftRevision`、`idempotencyKey`、结构化 `answers`、`page` 与 `collapsed`。`interaction/respond` 用 `expectedRevision` 和幂等键原子提交答案、原 ToolResult 与恢复游标；`interaction/cancel` 明确取消，收起卡片不调用它。答案区分稳定选项、自填和跳过，最多三题；服务端重新校验必答及选项归属。等待不自动超时同意，也不授予执行权限。

`plan/current/read {threadId}` 返回 nullable `current`；`plan/observe {threadId,planId}` 返回快照及观察句柄。Plan 独立事件和证据分别通过 `plan/events/read`、`plan/evidence/list` 分页，后者必须绑定 `planRevisionId` 与 `runId`。

`plan/execute` 绑定用户看到的版本与 hash，在单个事务中授权并创建 Run。`plan/pause`、`plan/resume`、`plan/stop` 接受 `{threadId,planId,expectedPlanRevision,runId,idempotencyKey}`，不通过 Goal 控制或模式切换间接执行。草稿定稿仍使用 `plan/propose`，界面显示“完成编辑”；用户开始执行只点击“执行”。
